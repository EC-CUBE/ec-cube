# 脅威モデル

EC-CUBE 4.3 は PHP 製のオープンソースの EC サイト構築パッケージです。購入者向けの店頭と、店舗運営者向けの管理画面を持ちます。
個人情報（会員・お届け先）、受注、金額、管理者の権限を扱います。

## 信頼できない入力の入口

- **店頭（未ログイン）**: 商品一覧・詳細、カート、会員登録、パスワード再設定、お問い合わせ、ゲスト購入。ここから入る値はすべて信頼しません
- **会員（マイページ）**: 受注履歴、お届け先、お気に入り、会員情報の変更。他の会員のデータへ届かないことが重要です
- **管理画面（`/admin` 配下、管理者ログイン後）**: 権限を制限した管理者が、権限外の画面・データへ届かないことが重要です
- **CSV アップロード**（商品・会員などの一括登録）、**ファイル管理・アップロード**、**テンプレートやコンテンツの編集**
- **外部からの通知**: 決済事業者からの通知やコールバック（プラグイン経由）
- **プラグイン**: 実行時に追加されるコードです。プラグイン自体の不具合は対象外です（下記）。本体がプラグインへ渡す値の扱いは対象です

## 守る資産

- 会員の個人情報（氏名・住所・電話番号・メールアドレス・受注履歴）
- 受注と金額（数量・価格・送料・手数料・値引き・ポイントの整合性）
- 管理者の権限と認証情報、サイトの設定

## 利用者の種類ごとにできてよいこと

| 利用者 | できてよいこと |
|---|---|
| ゲスト | 商品の閲覧、カート、ゲスト購入。他人のデータには触れない |
| 会員 | 自分のデータの参照・変更だけ |
| 権限を制限した管理者 | 付与された権限の範囲の画面・データだけ（権限外の URL を直接開いても拒否される） |
| システム管理者 | 管理画面のほぼすべて。信頼する（下記） |

## 重視するクラス

- 認可の欠陥: 他の会員の受注・お届け先などを ID の書き換えで参照・更新できる（IDOR）。権限を制限した管理者の権限昇格
- 金額・状態の改ざん: 数量・価格・送料・ポイントの改ざん、二重送信、決済前の受注の確定。`PROCESSING` / `PENDING` は確定前の仮受注です
- SQL インジェクション、XSS（特に管理画面で表示される、店頭からの入力）、CSRF、パストラバーサル、安全でないファイルのアップロード、SSRF
- 認証の欠陥（ログインの回避、パスワード再設定の欠陥、セッションの固定）

## 対象外・低く評価するもの

- **システム管理者が前提の操作**（テンプレートや CSS・JS の編集、プラグインの導入、ファイル管理など、管理画面の機能として許可している操作）。システム管理者は信頼します。ただし、権限を制限した管理者がこれらに届く場合は対象です
- サーバーへ shell で入れる人、DB に直接つなげる人が前提のもの
- プラグインの不具合、同梱していないサードパーティのコード
- 本番では無効にする設定（デバッグ表示など）を有効にした場合だけ起きるもの
- `vendor` 配下のライブラリ自体の既知の脆弱性。ただし EC-CUBE の使い方で外部の入力から届く場合は報告してください

## 深刻度の目安

- **critical**: 認証なしで PHP コードの実行、任意のファイルの読み書き、データベース全体の読み出し
- **high**: 認証なし、または会員権限で、他人の個人情報の参照・変更（IDOR）。権限を制限した管理者による、システム管理者の権限の取得。認証なしの SQL インジェクション
- **medium**: 管理画面での Stored XSS（店頭からの入力が原因のもの）、CSRF による重要な設定の変更、金額の改ざんのうち限定的なもの
- **low**: 情報の漏えいのうち影響が小さいもの、利用者の操作が必要で影響が限られるもの

## 試し方

- テストは `tests/Eccube/Tests` にあります。DB は SQLite（`var/eccube.db`）で、スキーマとフィクスチャを作成済みです
- ルートは `bin/console debug:router` で一覧できます。認可は `app/config/eccube/packages/security.yaml` と、管理画面の権限設定（`dtb_authority_role` の `deny_url`）で決まります

## 報告の希望

- 再現手順（リクエスト、前提となる権限）と、修正案を含めてください
- 管理画面の機能として意図された動作かどうか、利用者の種類ごとの許可（上の表）と照らして判断してください
